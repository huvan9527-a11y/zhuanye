# 模拟账户日常操作与纪律

本手册是项目的正式运行规范，随代码长期维护。模拟账户只用于按 Olenara 已审核策略观察资金曲线；不连接券商，也不发真实订单。所有成交和收益均是依赖公开行情的估算结果。

## 每个交易日的固定流程

1. **盘前工作流（北京时间 09:20 启动）**：读取上一交易日已提交的账本，抓取策略原文、竞价和 09:35–09:50 分钟线；按竞价条件与确认窗口选择至多一只标的。只有账户空仓且行情齐全时才计算买入股数。
2. **记账**：先按当前权益的 20% 和可用现金取较小值，预留手续费，再按 100 股整数手向下取整。交易事件、费用、剩余现金、来源和滑点假设完整校验后才写入账本。
3. **盘后工作流（北京时间 15:05）**：读取已提交账本和持仓股票当日完整分钟线。只有符合 T+1 的持仓才评估 -3% / -5% 止损及连续五分钟低于均价线的退出规则；估算退出后更新现金和盈亏。
4. **每日估值**：用可核验的当日收盘分钟价更新持仓市值、现金、净值、累计收益和回撤。缺少或过期行情时保留上次核验价并把净值标为不完整，不以旧价宣称当日收益。
5. **提交与核查**：成功并通过账本校验后，Actions 才把账户文件、行情快照和报告提交回仓库。早盘与盘后运行共用并发锁，避免两个运行基于旧状态覆盖彼此。

## 每天的核查顺序

打开 Actions 中当天两次运行，先确认工作流成功且 Summary 没有数据警告，再依次核查：

1. `reports/YYYY-MM-DD-report.md`：策略来源、竞价结果、入场候选、数量、成交额、费用和可用现金。
2. `reports/YYYY-MM-DD-account-close.md`：盘后持仓、卖出事件、收盘估值、净值完整状态。
3. `data/paper_account/trades.csv`：逐笔买卖事件、股数、估算价格、费用、来源、事件 ID 和 `origin`。
4. `data/paper_account/positions.csv`：当前持仓及其成本、最新可核验估值时间和 T+1 可卖日期。
5. `data/paper_account/daily_nav.csv`：每日现金、持仓市值、净值、实现/未实现盈亏、累计收益和回撤。
6. `data/signals/YYYY-MM-DD/` 与 `data/market/`：原始策略快照及行情输入，用来复核信号和估算成交。

仓库中的上述文件是跨运行的正式账本；Actions artifact 仅作当次诊断副本。不要只根据某一天的浮盈判断策略长期有效。账户净值包含费用，但不包含股息、公司行为和退市处理。

## 交易与数据纪律

- **信号不等于成交。** 只有满足竞价、分钟确认、空仓、资金、股数取整和费用条件并成功写入交易事件后，报告才可列为已记账估算成交。
- **估算不冒充实盘。** 每笔成交都标记来源、时间（若有）、执行规则、滑点和 `live_run` / `backfill` 来源。公开分钟线不能证明盘口排队成交。
- **不重复买入。** 同一天事件 ID 唯一；重复运行应识别已记账事件，不得再次扣款。持仓未退出时不加仓，也不换成另一个候选。
- **遵守 T+1。** 买入当日不可卖出；没有下一交易日日期或交易日历失败时，应记录明确回退来源，不猜测节假日。
- **不猜行情、不猜成交。** 竞价、分钟线、均价、收盘价缺失或数据陈旧时，停止该动作并报告不完整；不把缺失值补成零。
- **不隐去费用。** 配置文件中的佣金是假设值，应按实际账户修改；报告应单列佣金、过户费、卖出印花税和滑点。
- **不自行添加卖出策略。** 目前只执行已记录的止损及均价线退出；没有止盈目标或最大持仓天数时就继续持有并按收盘价估值。
- **不直接改写历史。** 不手工删改旧成交、原始快照或净值行。发现错误时先备份并走下面的更正流程。

## 首次初始化和 2026-10-12 回放

`data/paper_account/trades.csv` 初始包含唯一一笔明确标为 `backfill` 的绿盟科技（300369）重建记录：1,700 股、估算价 ¥11.43、总成交额 ¥19,431。股数来自 10 万元初始资金、20% 仓位上限和 100 股整数手；这是根据旧版完整日志回放的模拟账务事件，**不是旧版程序真正记过的成交**。买入手续费按当前模拟配置计入账户。旧日志未包含 2026-10-12 收盘价，因此不补造当天收盘净值；首个有完整行情的盘后运行才给持仓建立核验估值。

该 backfill 使用固定事件 ID，初始化函数必须幂等。若仓库中账本为空但账户已有历史，不要清空后重跑；先检查 Git 历史，恢复完整账本。

## 失败、恢复与更正

- **盘前工作流失败**：不把部分行情/信号数据写成成交。查看 artifact 日志和数据警告；先确认分支仍有最近一次成功提交的账本。修复数据或代码后，使用手动 preview 检查策略日期，preview 默认不改变账户。
- **盘后工作流失败**：最后一个成功提交的持仓与净值仍为正式状态。查看 artifact，确认行情是否完整。必要时手动触发 `Paper account after close` 指定目标日期；`commit_state` 默认 false，只有确认会生成正确且可对账的历史结果后，才显式选择 true。
- **行情缺失但任务完成**：这是不完整日而非零收益日。保留持仓，检查 `complete=NO` 和报告警告；等待下一次可核验行情，切勿把旧估值写成当日收盘价。
- **需要更正历史**：不得覆盖原事件。新增单独的 adjustment/reversal 事件和说明，更新净值并保留来源；更正必须能从交易事件重放得到同一现金、持仓和净值。
- **需要重置账户**：先在 GitHub 建立备份分支/标签，确认不会删除用户历史，再按团队约定手动操作。正常工作流不提供自动 reset 功能。

## 配置与费用

编辑 `config/paper_account.json`，费用和仓位规则的变更应在提交说明中写明生效日期；不得回算成历史已知条件。默认模拟假设为佣金 0.03%（每单最低 ¥5）、过户费 0.001% 双向、卖出印花税 0.05%、估算滑点 0.1%。佣金依账户约定而异，所有历史报告应记录所用配置值。遇到费率政策变化时先更新配置与说明，再以新值计算新交易。

- 配置：`config/paper_account.json`
- 逐笔账本：`data/paper_account/trades.csv`
- 当前持仓：`data/paper_account/positions.csv`
- 每日净值：`data/paper_account/daily_nav.csv`
- 盘前与盘后报告：`reports/`
- 自动运行：`.github/workflows/daily.yml`、`.github/workflows/daily-close.yml`
