# Olenara A股模拟交易流程

本仓库记录基于 Olenara 收盘复盘与盘前早报的 A 股模拟交易流程。初始资金为 ¥100,000，仅用于研究和模拟，不连接券商、不发送真实订单，也不构成投资建议。

> **数据原则：** GitHub Actions 不是实时行情终端。公开免费数据可能延迟、缺字段或限流。常规分钟 K 线不能证明 09:25 集合竞价成交。缺少可靠数据时必须标记数据缺失并放弃交易；估算成交不代表真实可成交。

## 每日流程

### 1. 确认交易日和策略来源

对目标交易日 `T`：

1. 优先通过 AkShare 交易日历确认上一交易日 `P`。
2. 首先抓取 `https://olenara.com/{P}-close.html` 收盘复盘。
3. 若收盘复盘抓取失败，或未解析到本项目支持的有效候选，再抓取 `https://olenara.com/morning-{T}.html` 盘前早报。
4. 两篇文章都没有有效策略时，记录 `NO_VALID_STRATEGY` 并严格空仓。
5. 保存原文快照、SHA256、抓取状态、解析说明和最终来源选择到 `data/signals/T/`。

若交易日历不可用，工作日回退会标记 `WEEKDAY_FALLBACK_NOT_HOLIDAY_AWARE`。它不识别中国法定休市日，运行前需人工核对交易日。只接受已审核规则中的候选代码，不自动加入未知股票。

### 2. 盘前准备

- 阅读最终选中的复盘或早报，确认策略日期、候选名单和各自条件。
- 检查可靠行情源是否提供竞价记录，以及数据文件是否包含目标日期。
- 不从开盘价反推 09:25 竞价，也不把缺失值补为 0。
- 若文章无有效候选、策略日期不符或数据源无法核实，保持空仓。

### 3. 09:25 集合竞价检查

读取 `data/market/auction.csv`，格式为：

```csv
date,code,auction_price,prev_close,auction_pct,source,observed_at
```

`auction_pct` 使用百分数数值，例如 `2.4` 表示上涨 2.4%。只能填写竞价结束后实际获得的记录，并在 `source` 中注明来源。

逐只核对文章或已审核规则设定的竞价门槛。以 2026-10-12 初始化候选规则为例：

| 股票 | 代码 | 竞价最低涨幅 | 额外规则 |
|---|---:|---:|---|
| 绿盟科技 | 300369 | +2% | 竞价不高于 0% 放弃 |
| 天融信 | 002212 | +2% | 平开观察 |
| 中文在线 | 300364 | +3% | 竞价不高于 0% 放弃 |
| 吉视传媒 | 601929 | +2% | — |
| 振华股份 | 603067 | +1.5% | — |

此候选表来自用户提供的 2026-10-12 初始化资料，仅作为该日期的手动备用，不代表网页解析结果，也不会默认自动启用。通常仅做表 A 候选，不主动买表 B，表 C 排除；若来源文章的策略不同，以该交易日有效来源和已审核规则为准。

### 4. 09:35–09:50 入场确认

读取 `data/market/minute_bars.csv`，格式为：

```csv
date,code,time,open,high,low,close,volume,amount,avg_price
```

只在 09:35–09:50 检查候选。需要有有效分钟数据，并同时符合策略条件：放量、价格不破规则参考位，且分钟收盘价不低于当日均价。均价优先使用数据源 VWAP；如用成交额/成交量近似，必须确认单位一致。

- 多只候选满足时，按竞价强度排序，只选一只。
- 单次仓位不超过 20%。
- 数据缺失、分钟确认失败或没有候选符合规则时，不交易。
- 估算买入价使用确认分钟收盘价加 0.1% 滑点，仅用于模拟，不是实际盘口成交承诺。

### 5. 持仓风控与退出

- 10cm 标的止损参考为 −3%；20cm 标的止损参考为 −5%。
- 跌破均价线且 5 分钟内未收回时退出。
- 只有文章明确给出止盈和持有期限时才按其执行；若文章未定义，报告注明“未定义”，不自行补造规则。
- 触及止损但遇跌停无法卖出的风险，简单模拟模型无法充分反映。

2026-10-12 原文另提到观察时代万恒、九阳股份的竞价情况。只有存在可靠竞价数据时才可人工评估这一条件；系统不据此自动把仓位提高到 20% 以上，缺数据时不猜。

### 6. 收盘后记录

运行模拟流程后，检查：

- `reports/YYYY-MM-DD-report.md`：每日说明和结果。
- `reports/YYYY-MM-DD-signals.csv`：候选信号、状态和原因。
- `data/signals/YYYY-MM-DD/source_decision.json`：来源选择、解析结果和候选代码。
- `data/signals/YYYY-MM-DD/`：复盘及早报快照。

账本、报告和持仓快照应区分真实输入与估算结果，所有估算成交标记为 `ESTIMATED`。如两个来源均无有效候选，输出 `NO_VALID_STRATEGY`，不交易。

## 运行方式

本地安装依赖后，可对指定日期运行模拟：

```bash
python -m venv .venv
# Windows
.venv\\Scripts\\activate
# macOS/Linux
source .venv/bin/activate
pip install -r requirements.txt

python -m src.main --strategy-date 2026-10-12 --dry-run
```

仅在需要显式使用用户提供的 2026-10-12 候选表进行初始化测试时，加上 `--allow-user-seed`：

```bash
python -m src.main --strategy-date 2026-10-12 --dry-run --allow-user-seed
```

没有当日可靠行情文件时，程序只输出信号与数据缺失，不虚构买入。默认策略来源无效时不会启用种子候选。

## GitHub Actions

工作流位于 `.github/workflows/daily.yml`：

- 手动运行时填写 `strategy_date`。
- 工作日 UTC 07:55（北京时间 15:55）定时运行，供收盘后抓取和报告使用，不用于 09:25 竞价或盘中决策。
- 报告与来源快照作为 `paper-trader-report` artifact 上传，保留 90 天。
- 默认仅授予 `contents: read`，不会自动提交生成文件到账本。
- GitHub 定时任务可能延迟；盘中决策需要本地常驻行情进程或可靠行情服务触发。

## 数据源和局限

- [Ashare](https://github.com/mpquant/Ashare)：公开源封装，分钟数据可用性、历史覆盖和时效需要逐日验证。
- [AkShare](https://github.com/akfamily/akshare)：免费开源数据接口，数据口径和限流情况可能变化。
- 不假定免费数据源稳定提供历史 09:25 集合竞价撮合数据；应优先人工导入可靠竞价快照。
- 网页结构变化、数据缺失或限流时，系统应宁可不交易，不把预置名单当作网页解析结果。
- 本工具不执行真实交易，不保证排队成交或止损成交；公开数据、复权口径和接口可用性均可能变化。
